# How much of a VA handover can be rebuilt from access logs?

## Research question and scope

This is a proposed research protocol, not a report of completed findings. It asks how much of a virtual assistant handover can be rebuilt from access logs and activity records when the written note is missing. The result would help a team judge whether logs are a useful recovery source. Keep the original note beside the corrected version.

The protocol does not test whether the handover was good. It tests whether the logs can reconstruct the work that the handover should have described. The sponsor should name the recovery decision the result could inform. Review the first few notes together before the process expands.

## Population and unit of analysis

Define the population as handovers during a stated period that have both a written note and system activity records. The unit is one handover, with the tasks, the systems touched, and the timestamps recorded. Handovers without a written note should be counted separately. Use the same format for every handover so the next reader can scan it.

Link the log events to the tasks they support. A login to a system is not evidence that a task was completed. The unit is the task-level reconstruction, not the raw event count. Keep the original note beside the corrected version.

## Definitions and measures

Define reconstruction as the ability of a reviewer to state the open task, the source, and the next action using only the logs. Define accuracy as the match between the reconstructed statement and the written note. Define coverage as the share of handover tasks that the logs can support. Name the owner in the same line as the action.

Report coverage and accuracy separately. A log may cover many tasks but misstate the next action. The combination is what determines whether the logs are usable. Ask whether a new reviewer could act on the record without a conversation.

## Evidence standard

Use a reviewer who did not create the original handover. Give the reviewer the logs and a blank template, then compare the result with the written note. Record the reviewer's confidence and the points where the logs were ambiguous. Test the rule on one real task before applying it to the queue.

Keep the original note and the reconstructed note side by side. A later discussion between the reviewer and the original assistant can explain differences, but it should not be used to improve the reconstruction before it is scored. Keep the evidence with the record rather than in a separate log. Keep the boundary visible in the place where the work is assigned.

## Sampling and collection

Use all eligible handovers in the window if the volume is manageable. If sampling is necessary, stratify by task type and system. Select the sample before reviewing the reconstruction and keep a log of replacements. Keep the boundary visible in the place where the work is assigned.

Pilot the reconstruction on a few handovers and compare two reviewers. Clarify how a log event that supports several tasks is counted. Record the rules and apply them consistently. Name the owner in the same line as the action.

## Analysis and reporting

Report coverage and accuracy by task type and by system. Show the tasks that could not be reconstructed at all. A high coverage rate with low accuracy may mean the logs show activity without explaining the work. Review the first few notes together before the process expands.

Present the results as a description of the logs, not a judgment about the assistant. Logs record what a system saw, not what the person intended. Name the gaps that the written handover still needs to fill. If the source is unclear, route the question instead of guessing.

## Limits and sources of error

Access logs may be retained for a shorter period than the handover, or they may be incomplete because a task was done offline. The study should state the retention window and the systems included. Name the owner in the same line as the action. A control that depends on memory is not yet a control.

The reviewer's familiarity with the work can inflate the reconstruction. Use a reviewer who is new to the account where possible. Record the reviewer's background. Record the observation time so the next reviewer can tell when the evidence was checked.

## Review cadence

Repeat the review after a system change or a retention change. Compare the same task types and the same reconstruction method. A second review can test whether the logs are a stable recovery source. Update the template when the same question appears twice.

Assign the follow-up to the operations owner and set a date. The protocol should produce a specific decision about whether the handover template needs a field that the logs cannot supply. Keep the original note beside the corrected version. A short note with four fields is easier to use than a long narrative.
