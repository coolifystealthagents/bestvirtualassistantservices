# What does a response-time target hide about queue quality?

## Research question and scope

This is a proposed research protocol, not a report of completed findings. It asks what a response-time target hides about the quality of the queue behind it. The result would help a team judge whether the target is a useful service measure. Record the exception and the person who approved it.

The protocol does not measure the assistant's effort. It measures the relationship between the first response, the resolution, and the reopened work. The sponsor should name the service decision the result could inform. Write the deadline as a date and a local time.

## Population and unit of analysis

Define the population as all client requests that received a first response during a stated period. The unit is one request, with the arrival time, first response time, resolution time, and reopening status recorded. Requests that were withdrawn should be counted separately. A short note with four fields is easier to use than a long narrative.

Link follow-up messages to the original request so a reply that creates more work is not counted as a clean resolution. The request-level view is the unit, not each message. Write the deadline as a date and a local time. Keep the evidence with the record rather than in a separate log.

## Definitions and measures

Define first response as the first substantive reply that names a next step or asks a specific question. Define resolution as the point when the client's need is met or the request is formally closed. Define reopening as a new message on the same need after closure. If the source is unclear, route the question instead of guessing.

Report the first-response time, the resolution time, and the reopening rate together. A fast first response with a high reopening rate may be worse than a slower, complete response. Keep the evidence with the record rather than in a separate log. Test the rule on one real task before applying it to the queue.

## Evidence standard

Use system timestamps for arrival and first response where possible. For resolution, use the record that shows the client's need was met. If the only evidence is a chat message, record the sender and the time. Ask whether a new reviewer could act on the record without a conversation.

Keep the original request and the later messages. A summary that says the client was happy does not prove resolution. The study should distinguish the evidence available at each stage. Test the rule on one real task before applying it to the queue.

## Sampling and collection

Use a census of the period if the volume is manageable. If sampling is necessary, stratify by request type and by channel. Select the sample before reviewing reopening and keep a log of replacements. Use the same format for every handover so the next reader can scan it.

Pilot the classification on a few requests and compare the reviewers' judgments. Clarify what counts as a substantive first response. Record the rule and apply it consistently. Ask whether a new reviewer could act on the record without a conversation.

## Analysis and reporting

Report the distribution of first-response and resolution times, not only the averages. Show the reopening rate by response-time band. A fast band with a high reopening rate is a warning, not a success. Update the template when the same question appears twice.

Describe the queue conditions that may explain the pattern, such as request mix or staffing. Avoid claiming that a faster response causes a better outcome. The result is a description of the relationship. Separate what was observed from what was assumed.

## Limits and sources of error

The first response may be automated or templated, which can make the time look better without improving the client experience. The study should identify automated replies and treat them separately. Test the rule on one real task before applying it to the queue. Review the first few notes together before the process expands.

The resolution record may depend on the assistant's own judgment. A request marked resolved may still be open in the client's view. State how resolution was verified. Ask whether a new reviewer could act on the record without a conversation.

## Review cadence

Repeat the review after a target change or a queue redesign. Compare the same response bands and the same reopening definition. A faster target is useful only if the resolution and reopening measures hold. Use the same format for every handover so the next reader can scan it.

Assign the follow-up to the service owner and set a date. The protocol should produce a specific decision about the target, the first-response standard, or the queue design. Separate what was observed from what was assumed. Keep the evidence with the record rather than in a separate log.
