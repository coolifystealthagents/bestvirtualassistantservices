# Virtual Assistant File Naming for Client Work

Consistent names reduce the time spent asking which document is current. A useful standard tells a person what the file is, which client or project it belongs to, and what date or revision matters.

## Virtual Assistant File Naming for Client Work: choose stable fields

Use a short project identifier, document type, subject, and ISO date where a date is meaningful. Avoid names that depend on a person’s memory or a temporary folder location.

## Keep revisions understandable

Choose one revision convention and explain whether the number refers to an internal draft or an approved issue. Never use final-final or latest as a version signal.

## Handle exceptions deliberately

Legal holds, client-provided names, and system-generated exports may need exceptions. Record the reason and preserve the original reference. The [document naming standard](/blog/virtual-assistant-document-naming-standard) and [document control guide](/blog/virtual-assistant-document-control) offer complementary checks.

## Make the standard easy to follow

Show three good examples and two common mistakes. Put the rule near the intake point so it is applied before files multiply.

## Protect the file set

Limit names to information that should be visible in the workspace. For access and sharing considerations, review [NIST small business cybersecurity guidance](https://www.nist.gov/itl/smallbusinesscyber). A naming rule improves findability without becoming a place to store sensitive detail.
