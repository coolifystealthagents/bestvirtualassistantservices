# Virtual assistant file migration controls

Define source, destination, scope, naming rule, owner, and stop condition. This guide is for buyers and operators who need a clear role boundary before assigning work to a Philippines-based virtual assistant.

## Virtual assistant file migration controls starts with a clear brief

Start with a sample. The assistant maps and records exceptions; the owner decides what to delete or restrict. Put the expected output, source of truth, review owner, and stop condition in the brief. If the request changes, record the change instead of quietly expanding the role.

## Keep preparation separate from decisions

Check samples, permissions, and links after transfer. Stop when the destination differs from the brief. The virtual assistant can gather context, normalize records, flag missing evidence, and prepare a review queue. The accountable owner keeps decisions involving commitments, sensitive information, public statements, or irreversible changes.

## Make the handoff easy to inspect

At handoff, include completed work, unresolved questions, source links, next owner, and review date. ## Frequently asked questions

### What should the owner define first?

Define the intended outcome, source of truth, reviewer, and approval boundary before assigning the first task.

### When should the virtual assistant escalate?

Escalate when information is missing, the request leaves the brief, a sensitive decision is involved, or the expected result cannot be checked.

### What makes a handoff ready?

A new reviewer can understand status, evidence, open questions, and next action without reconstructing a private conversation.
