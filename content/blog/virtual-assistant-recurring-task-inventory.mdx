# Virtual Assistant Recurring Task Inventories

For recurring task inventories, begin with the record that makes the next decision possible, then keep the owner and stopping point visible.

## Virtual Assistant Recurring Task Inventories: Inventory the work that repeats

Start with calendars, shared checklists, inbox rules, and recent handoffs. Record the task name, trigger, expected result, owner, backup, and last evidence of completion. The aim is not to make every activity formal; it is to reveal work that depends on memory alone.

## Test whether a task still earns its place

For each recurring item, ask what decision or obligation it supports. Check whether the frequency still matches the need and whether two tasks produce the same result. Retire or combine items that no longer have a clear consumer.

## Describe the finish line

A task is complete when a named result exists, not when someone spent time on it. Define the artifact, update, message, or review that proves completion. Include a pause condition for missing inputs or an exception that needs owner judgment.

## Plan for absences

A backup person needs the source location, due window, expected result, and escalation contact. Avoid transferring broad access just to cover one small task. A compact coverage note is safer and more useful than an undocumented promise to remember.

## Review the inventory after change

Revisit recurring work after a system change, new responsibility, or missed deadline. Keep the history of why frequency or ownership changed. The [GSA technology services guidance](https://www.gsa.gov/technology/it-contracting/technology-products-services) is a useful prompt to treat operating tools and responsibilities as managed resources.


## Keep the decision visible

For this topic, preserve the source and route uncertainty to the named owner.
