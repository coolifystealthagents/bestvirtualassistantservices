# Virtual Assistant Returns Data Reconciliation

For returns data reconciliation, begin with the record that makes the next decision possible, then keep the owner and stopping point visible.

## Virtual Assistant Returns Data Reconciliation: Define the records being compared

A returns reconciliation joins customer, order, shipment, refund, and inventory records that were created for different purposes. Write down the fields used to match them and the time window covered. Without that boundary, a mismatch can be a delayed event rather than an error.

## Match with a hierarchy

Use the strongest shared identifier first, then consider order line, product code, date, and amount. Keep one-to-many and partial returns visible. Never force a match because two rows look similar. An unresolved pair is safer than a refund assigned to the wrong order.

## Explain each difference

Classify exceptions such as timing, duplicate entry, quantity disagreement, missing refund, or policy decision. Add the source records and the next person who can resolve the item. Categories make a long exception list actionable without pretending every cause is known.

## Reconcile money separately

Compare authorized refund, processed refund, payment status, and customer communication as separate facts. Do not mark a return complete because inventory moved. Financial exceptions need the owner who can approve or investigate them.

## Keep customer promises accurate

If the business has promised a response or refund, record the promise and its due point. Route delays quickly and avoid making a new promise without authority. The FTC’s [Mail, Internet, or Telephone Order Merchandise Rule guidance](https://www.ftc.gov/business-guidance/resources/business-guidance-mail-internet-or-telephone-order-merchandise-rule) provides useful context for timely order and refund communication.


## Keep the decision visible

For this topic, preserve the source and route uncertainty to the named owner.
