# Virtual Assistant Task Dependency Notes

A dependency note explains why one task cannot move, what it needs, and who can change the situation. It turns a vague blocked label into a useful question for the accountable owner.

## Virtual Assistant Task Dependency Notes: name the predecessor

State the task that must happen first and the evidence that it is incomplete. Use identifiers that another person can locate without reconstructing the project from memory.

## Describe the effect

Explain which deliverable or date is affected, using the smallest accurate claim. Do not turn a missing input into a prediction about the entire project.

## Assign the next question

Name the person who can provide the input or decide an alternative. The [dependency map guide](/blog/virtual-assistant-task-dependency-map) supports structure, and the [task prioritization guide](/blog/virtual-assistant-weekly-task-prioritization) helps sequence available work.

## Review stale blockers

Set a review date and close the note when evidence shows the dependency is resolved. If it changes shape, update the note rather than hiding the history.

## Keep project records safe

Link to approved sources and avoid copying confidential content into status fields. See [NIST small business cybersecurity guidance](https://www.nist.gov/itl/smallbusinesscyber) for access guidance.
