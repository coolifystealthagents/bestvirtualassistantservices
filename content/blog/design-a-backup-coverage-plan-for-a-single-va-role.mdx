# Design a backup coverage plan for a single VA role

## How to approach: Design a backup coverage plan for a single VA role

A backup plan starts with the work that cannot wait for the primary assistant to return. List the recurring tasks, the deadlines, and the people who depend on them. Separate work that can pause from work that must continue. The plan should cover the must-continue work first.

Name the backup person and confirm that the person has the access and context to do the work. A plan that names someone who has never seen the queue is not coverage. Test the plan on a normal day before an absence makes it urgent. Review the first few notes together before the process expands.

## List the tasks and their deadlines

Write each task with its frequency, deadline, source, and output. Include the tasks that happen only on certain days, because those are the ones a backup is most likely to miss. Mark the tasks that require a decision from the client or the manager. A backup can prepare those tasks but may not be able to close them.

Rank the tasks by the cost of a missed deadline. A payroll input and a weekly report do not carry the same consequence. Use the ranking to decide what the backup does first when time is short. The plan should be honest about what will be delayed.

## Confirm access before the absence

Check that the backup can open the systems, folders, and templates needed for the must-continue work. Test the access on a normal day rather than the first morning of an absence. Record any access that requires a manager approval and start that request early. A plan that depends on a password reset is not ready.

Keep shared credentials out of the plan. Use named accounts and approved access paths. If a task requires a permission the backup does not have, either arrange the permission in advance or name the person who will perform that step. The plan should not create a security shortcut.

## Write the handover note

The handover note should name the open tasks, the next deadlines, the contacts, and the decisions that are pending. Link the source records rather than pasting long histories. Include the customer preferences and the escalation path. The backup should be able to start without a meeting.

Keep the note current during the absence. A handover that is accurate on day one but stale on day three will mislead the backup. Set a short daily update for the tasks that change. The update can be a few lines if it names what moved and what is next.

## Set the decision boundary

State clearly what the backup may decide and what must wait for the primary or the manager. A routine reschedule may be fine, while a refund or a contract change is not. Name the person who can approve the exception. The boundary protects the client and the backup.

Record the boundary in the same place the work is assigned. A boundary that lives only in a policy document will be missed under pressure. Review it with the backup before the absence begins. A short note with four fields is easier to use than a long narrative.

## Test and improve the plan

Run a short test on a normal day: have the backup complete one must-continue task while the primary observes. Note where the backup had to ask a question. Those questions are the gaps in the plan. Fix the note or the access before the real absence.

After the absence, review what worked and what caused stress. Update the task list, the access, and the handover template. A coverage plan is a living document, not a one-time checklist. A short note with four fields is easier to use than a long narrative.
