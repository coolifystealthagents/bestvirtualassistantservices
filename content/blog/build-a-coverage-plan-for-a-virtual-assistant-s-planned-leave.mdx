# Build a coverage plan for a virtual assistant's planned leave

## How to approach: Build a coverage plan for a virtual assistant's planned leave

A coverage plan should start with the work that cannot wait. Name the tasks, the backup, the access, and the handover date. A plan that names only a backup person is not coverage. Ask whether a new reviewer could act on the record without a conversation. A short note with the requester and the next action is easier to use.

Keep the plan short enough to test before the leave. The backup should be able to start without a meeting. A control that depends on memory is not yet a control. Record the date and the source so the next reviewer can repeat the check. The handoff should say what the next person may decide without asking. The assistant should record the owner and the date before the next shift.

## List the must-continue tasks

Record the tasks with a client deadline, a payment, or a compliance requirement. Mark the tasks that can pause. A backup who tries to do everything will do the important work poorly. Record the exception and the person who approved it. Keep the source link with the task so the next reviewer can check it. The handoff should say what the next person may decide without asking.

Name the owner and the next date for each task. A task without an owner will be missed. A control that depends on memory is not yet a control. Keep the evidence with the record rather than in a separate log. Keep the source link with the task so the next reviewer can check it.

## Confirm the access and the handover

Check that the backup can open the systems and the files. Test the access before the leave. Record any pending approval and the person who owns it. Record the date and the source so the next reviewer can repeat the check. Test the brief on one real task before applying it to the whole role. The assistant should record the owner and the date before the next shift.

Set the handover date and the channel. The handover should include the open tasks, the contacts, and the decisions that must wait. If the source is unclear, route the question instead of guessing. Write the deadline as a date and a local time. The client should know who is handling the question and when to expect an answer.

## Set the decision boundary
