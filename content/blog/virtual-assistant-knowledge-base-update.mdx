# Virtual Assistant Knowledge Base Update Checklist

Virtual Assistant Knowledge Base Update Checklist explains how to delegate knowledge base update while keeping the owner’s decisions visible.

## Virtual Assistant Knowledge Base Update Checklist: start with the source

knowledge base update starts with approved answer, change reason, effective date, and policy owner. Those fields identify the record and the detail that can change the answer.

## Virtual Assistant Knowledge Base Update Checklist: notice the real risks

knowledge base update has a different risk profile: contradictory pages, silent edits, and advice without a current owner. Compare the record with its source instead of filling a gap from memory.

## Virtual Assistant Knowledge Base Update Checklist: write a bounded request

Write a bounded request for knowledge base update around approved answer, change reason, effective date, and policy owner. Name the result so a person who did not do the work can inspect it.

## Virtual Assistant Knowledge Base Update Checklist: preserve disagreements

If knowledge base update produces disagreement, retain both entries and identify the decision owner. Mark any proposed correction as proposed.

## Virtual Assistant Knowledge Base Update Checklist: keep authority clear

For knowledge base update, written authority may cover sorting, drafting, checking, and flagging. Sensitive approval and irreversible change remain owner decisions.

## Virtual Assistant Knowledge Base Update Checklist: show the exception

Build a normal example and a pause example from approved answer, change reason, effective date, and policy owner. The pause example records the evidence, uncertainty, and question that travels onward.

## Virtual Assistant Knowledge Base Update Checklist: make completion observable

Close knowledge base update with its source, change, unresolved item, and next action. A generic status cannot show whether review is still waiting.

## Virtual Assistant Knowledge Base Update Checklist: protect the record

Protect knowledge base update with the smallest necessary record. The [NIST small-business cybersecurity guidance](https://www.nist.gov/itl/smallbusinesscyber) gives a useful baseline.

## Virtual Assistant Knowledge Base Update Checklist: ask before closing

Before knowledge base update changes hands, check approved answer, change reason, effective date, and policy owner and leave contradictory pages, silent edits, and advice without a current owner visible where they affect the decision. See the [virtual assistant delegation guide](/blog/virtual-assistant-delegation-readiness) and [document review process](/blog/virtual-assistant-document-review-process).

### Owner inputs for knowledge base update

Supply approved answer, change reason, effective date, and policy owner.

**Approved answer** belongs in the knowledge base update brief because it changes what the reviewer can confirm.

**Change reason** belongs in the knowledge base update brief because it changes what the reviewer can confirm.

**Effective date** belongs in the knowledge base update brief because it changes what the reviewer can confirm.

**And policy owner** belongs in the knowledge base update brief because it changes what the reviewer can confirm.

### Owner decisions
Keep approvals, policy interpretation, and irreversible changes with the responsible owner.

Watch contradictory pages in knowledge base update; if it appears, preserve the evidence and ask for the named decision.

Watch silent edits in knowledge base update; if it appears, preserve the evidence and ask for the named decision.

Watch and advice without a current owner in knowledge base update; if it appears, preserve the evidence and ask for the named decision.

If approved answer is absent, knowledge base update should pause before the record is treated as complete.

Use change reason to distinguish a standard case from an exception in knowledge base update.

Check effective date against the source before a reviewer accepts knowledge base update.

Keep and policy owner beside the handoff when knowledge base update crosses to another person.

An owner can resolve contradictory pages faster when knowledge base update preserves the original evidence.

Do not hide silent edits behind a clean status in a knowledge base update report.

Route and advice without a current owner with a named question rather than a guess about knowledge base update.

Later review of knowledge base update should be able to reconstruct why approved answer was accepted.

For knowledge base update, a correction is complete only after change reason has an observable result.

The owner’s rule for knowledge base update should say what happens when effective date and and policy owner disagree.
