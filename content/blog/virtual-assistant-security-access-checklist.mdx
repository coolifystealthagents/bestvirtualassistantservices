# Virtual Assistant Security and Access Checklist

A practical way to prepare permissions, shared records, and review boundaries before remote administrative support begins.

## Virtual Assistant Security and Access Checklist: Security and access planning starts with the smallest useful permission

A new support role should begin with a map of the systems, records, and decisions involved. Separate reading, drafting, editing, and approval rights. A short access register should name the tool, purpose, owner, requested level, and removal date. This keeps a helpful role from quietly becoming an unrestricted one.

## Build a handoff that protects customer information

Use named accounts where possible, multifactor authentication, a password manager, and a written rule for exports and screenshots. Give the assistant examples that have been sanitized, then review the first live items closely. The document review guide is a useful companion when files contain personal or commercial information.

## Review access as the role changes

Remove unused permissions after a project, check shared folders on a recurring cadence, and record who approved any expansion. NIST small-business guidance offers a useful baseline for access and account hygiene: [NIST small-business cybersecurity guidance](https://www.nist.gov/itl/smallbusinesscyber)

## Frequently asked questions

### What should the owner provide first?

Provide the source of truth, approved examples, the expected output, the reviewer, and a clear rule for exceptions.

### What should remain with the owner?

Keep approvals, policy interpretation, sensitive decisions, and irreversible changes with the responsible owner.
