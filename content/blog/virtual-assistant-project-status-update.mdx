# Virtual Assistant Project Status Update Format

Virtual Assistant Project Status Update Format explains how to delegate project status update while keeping the owner’s decisions visible.

## Virtual Assistant Project Status Update Format: start with the source

project status update starts with completed work, milestone, dependency, and decision request. Those fields identify the record and the detail that can change the answer.

## Virtual Assistant Project Status Update Format: notice the real risks

project status update has a different risk profile: green statuses, hidden blockers, and updates that force the reader to guess. Compare the record with its source instead of filling a gap from memory.

## Virtual Assistant Project Status Update Format: write a bounded request

Write a bounded request for project status update around completed work, milestone, dependency, and decision request. Name the result so a person who did not do the work can inspect it.

## Virtual Assistant Project Status Update Format: preserve disagreements

If project status update produces disagreement, retain both entries and identify the decision owner. Mark any proposed correction as proposed.

## Virtual Assistant Project Status Update Format: keep authority clear

For project status update, written authority may cover sorting, drafting, checking, and flagging. Sensitive approval and irreversible change remain owner decisions.

## Virtual Assistant Project Status Update Format: show the exception

Build a normal example and a pause example from completed work, milestone, dependency, and decision request. The pause example records the evidence, uncertainty, and question that travels onward.

## Virtual Assistant Project Status Update Format: make completion observable

Close project status update with its source, change, unresolved item, and next action. A generic status cannot show whether review is still waiting.

## Virtual Assistant Project Status Update Format: protect the record

Protect project status update with the smallest necessary record. The [NIST small-business cybersecurity guidance](https://www.nist.gov/itl/smallbusinesscyber) gives a useful baseline.

## Virtual Assistant Project Status Update Format: ask before closing

Before project status update changes hands, check completed work, milestone, dependency, and decision request and leave green statuses, hidden blockers, and updates that force the reader to guess visible where they affect the decision. ### Owner inputs for project status update

Supply completed work, milestone, dependency, and decision request.

**Completed work** belongs in the project status update brief because it changes what the reviewer can confirm.

**Milestone** belongs in the project status update brief because it changes what the reviewer can confirm.

**Dependency** belongs in the project status update brief because it changes what the reviewer can confirm.

**And decision request** belongs in the project status update brief because it changes what the reviewer can confirm.

### Owner decisions
Keep approvals, policy interpretation, and irreversible changes with the responsible owner.

Watch green statuses in project status update; if it appears, preserve the evidence and ask for the named decision.

Watch hidden blockers in project status update; if it appears, preserve the evidence and ask for the named decision.

Watch and updates that force the reader to guess in project status update; if it appears, preserve the evidence and ask for the named decision.

If completed work is absent, project status update should pause before the record is treated as complete.

Use milestone to distinguish a standard case from an exception in project status update.

Check dependency against the source before a reviewer accepts project status update.

Keep and decision request beside the handoff when project status update crosses to another person.

An owner can resolve green statuses faster when project status update preserves the original evidence.

Do not hide hidden blockers behind a clean status in a project status update report.

Route and updates that force the reader to guess with a named question rather than a guess about project status update.

Later review of project status update should be able to reconstruct why completed work was accepted.

For project status update, a correction is complete only after milestone has an observable result.

The owner’s rule for project status update should say what happens when dependency and and decision request disagree.
