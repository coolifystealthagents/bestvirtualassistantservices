# Write a virtual assistant brief that names the first deliverable

## How to approach: Write a virtual assistant brief that names the first deliverable

A virtual assistant brief should make the first deliverable obvious. Name the output, the source, the boundary, and the review date. A brief that only lists responsibilities leaves the assistant to guess what to produce first. Record the date and the source so the next reviewer can repeat the check.

Keep the brief to one page. The assistant should be able to start without a meeting. A brief that needs a meeting to explain is not ready. If the source is unclear, route the question instead of guessing.

## Name the first deliverable

Write the first output as a specific artifact, such as a cleaned contact list or a drafted reply. A deliverable that says help with the inbox is not testable. The assistant should know what done looks like. Record the date and the source so the next reviewer can repeat the check.

Record the format, the audience, and the deadline. A draft for internal review is different from a final client message. The brief should say which one applies. Name the owner in the same line as the action.

## Record the source and the boundary

Name the system of record and the approved sources. Record what the assistant may change and what needs approval. A boundary that is only in a policy file will be missed. Record the date and the source so the next reviewer can repeat the check.

Include the escalation path for missing information. The assistant should know who to ask and how quickly. Escalation is a normal step, not a failure. Separate what was observed from what was assumed.

## Set the review and the feedback

Decide who reviews the first deliverable and when. Record the feedback format and the next step. A review without a date will slip. Record the date and the source so the next reviewer can repeat the check.

Keep the feedback specific. A comment that says improve it is not actionable. A comment that names the missing source is actionable. Review the first few notes together before the process expands.

## Review the brief after the first deliverable

Ask the assistant what was unclear and update the template. A brief that improves after each use is more valuable than a perfect template. Record the exception and the person who approved it. Ask whether a new reviewer could act on the record without a conversation.

Share the best briefs with the team. A short example teaches more than a policy. Update the template when the same question appears twice. Ask whether a new reviewer could act on the record without a conversation.
